# Contributing to byterefs

Thanks for your interest. byterefs is an open specification and contributions
of all kinds are welcome: questions, use cases, implementation reports, and
changes to the text.

## Ways to contribute

- **Ask a question or report a problem.** Open an issue in the relevant
  repository. If you are not sure where, open it in the specification
  repository, [byterefs/spec](https://github.com/byterefs/spec).
- **Propose a change to the specification.** Open an issue first using the
  "Specification proposal" template, so the idea can be discussed before
  anyone writes text. An accepted proposal becomes a numbered decision
  record in `decisions/`, proposed in a pull request; the specification
  text changes when the record is accepted. Small fixes (typos, broken
  links, clarifications that do not change meaning) can go straight to a
  pull request.
- **Share an implementation.** Tell us about readers, writers or tools that
  produce or consume byte references, and which parts of the spec they cover.

## Pull requests

1. Fork the repository and create a branch for your change.
2. Keep each pull request focused on one change.
3. Describe what the change does and why, and link the issue it addresses.
4. For normative changes to the specification, say whether the change is
   backwards compatible with existing references.
5. Be ready to discuss and revise; review is part of the process.

## Writing style

- Use plain ASCII text in specification sources and code.
- Use RFC 2119 keywords (MUST, SHOULD, MAY) only for normative requirements.
- Prefer short examples that can be checked against an implementation.
